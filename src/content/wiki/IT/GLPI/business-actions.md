# Business Actions and Tasks

GLPI supports scheduled tasks (cron) to automate routine maintenance, such as sending reminders or synchronizing inventories. Administrators can manage these tasks from the setup menu or hook into external schedulers for advanced scenarios.

# Начало работы

GLPI содержит набор фоновых задач (crontasks), которые выполняются с заданной частотой. Для каждой задачи на странице “Автоматическое действие” можно настроить: **частоту**, **статус**, **режим выполнения (GLPI/CLI)**, **период (в какие часы разрешено)** и **сколько дней хранить логи**.

### Два режима запуска: GLPI и CLI

- **GLPI mode**: задачи “просыпаются” *только при активности пользователей в веб-интерфейсе* (когда кто-то открывает страницы GLPI). Ночью/в выходные или при редких заходах задачи могут почти не запускаться.
- **CLI mode**: задачи запускаются *в отдельном процессе* через **системный планировщик** (cron / Windows Task Scheduler). Это рекомендуемый режим, если нужно гарантированное выполнение.

Важно: **если задача выставлена в CLI, но системный планировщик не вызывает cron-движок GLPI - она будет выполняться только вручную из интерфейса.**

## Доступ GLPI к Cron системы

Данная ошибка связанна с доступом и по идее должна ломать все остальные CLI-скрипты.
В GLPI есть “движок крон-задач”, файл **`<GLPI>/front/cron.php` .** Его должен **раз в минуту** запускать планировщик ОС:

- на Linux  `cron`
- на Windows “Планировщик заданий”

GLPI сам внутри решает: *какие* задачи пора выполнить сейчас (раз в минуту он просто проверяет расписания). 

На примере нашей системы используется Linux+Apache, поэтому мы просто проверяем, что крон-движок запускается системой каждую минуту (от пользователя Apache - www-data):

```jsx
sudo crontab -u www-data -e
…
* * * * * /bin/php /var/www/glpi/front/cron.php
```
