# Постоянные маршруты в Windows: зачем нужны и как правильно настраивать

В Windows-системах (включая Windows Server) **постоянные маршруты** используются для управления тем, **через какой шлюз и интерфейс должен идти трафик к конкретным подсетям**.  
Это особенно важно в инфраструктурах с VPN, RDS, доменами и несколькими сетями.

Эта статья объясняет:
- зачем нужны постоянные маршруты;
- как Windows выбирает маршрут;
- как правильно добавлять маршруты;
- типичные ошибки и реальные кейсы.

---

## Что такое постоянный маршрут

**Постоянный маршрут** — это запись в таблице маршрутизации Windows, которая:
- задаёт путь к определённой сети или хосту;
- **сохраняется после перезагрузки**;
- имеет приоритет над default gateway при совпадении маски.

В Windows такие маршруты добавляются командой:

```cmd
route -p add ...
````

Ключ `-p` означает *persistent* — постоянный.

---

## Как Windows выбирает маршрут

При отправке IP-пакета Windows использует следующий алгоритм:

| Шаг | Критерий            | Пояснение                                    |
| --- | ------------------- | -------------------------------------------- |
| 1   | Самая длинная маска | `/32` > `/24` > `/16` > `/0`                 |
| 2   | Метрика             | Меньше = приоритет выше                      |
| 3   | Default route       | `0.0.0.0/0` используется в последнюю очередь |

### Пример

Если есть маршруты:

* `10.27.0.0/16 → VPN`
* `0.0.0.0/0 → Internet`

Трафик к `10.27.15.10` **всегда пойдёт через VPN**, даже если default gateway указывает в интернет.

---

## 🔍 Просмотр текущей таблицы маршрутов

Для просмотра маршрутов используется команда:

```cmd
route print
```

Вывод делится на:

* **Активные маршруты**
* **Постоянные маршруты**

### Пример фрагмента:

```
Сетевой адрес    Маска            Шлюз
10.1.0.0         255.255.0.0      10.1.216.100
0.0.0.0          0.0.0.0          95.56.228.145
```

---

## Когда нужны постоянные маршруты

Постоянные маршруты **обязательны**, если:

* используется **Site-to-Site или Client VPN**;
* сервер имеет **несколько интерфейсов**;
* часть корпоративных подсетей недоступна через default gateway;
* наблюдаются проблемы с:

  * RDS / RemoteApp
  * Kerberos / LDAP
  * доменной аутентификацией
  * лицензированием
  * RPC / SMB

> ❗ Firewall здесь ни при чём — это уровень **L3 (маршрутизация)**.

---

## Типовой корпоративный кейс

| Элемент         | Значение        |
| --------------- | --------------- |
| VPN-шлюз        | `10.1.216.100`  |
| VPN-подсеть     | `10.27.0.0/16`  |
| Default gateway | `95.56.228.145` |

**Проблема:**
Без маршрута трафик к `10.27.x.x` уходит в интернет → сервисы не работают.

---

## Добавление постоянного маршрута

### Синтаксис команды

```cmd
route -p add <NETWORK> mask <NETMASK> <GATEWAY> metric <METRIC>
```

### Реальный пример

Добавить постоянный маршрут для VPN-подсети:

```cmd
route -p add 10.27.0.0 mask 255.255.0.0 10.1.216.100 metric 1
```

### Что делает команда

| Параметр       | Значение                             |
| -------------- | ------------------------------------ |
| `-p`           | Сохраняет маршрут после перезагрузки |
| `10.27.0.0`    | Адрес сети                           |
| `255.255.0.0`  | Маска сети (/16)                     |
| `10.1.216.100` | VPN / L3-шлюз                        |
| `metric 1`     | Высший приоритет                     |

---

## Проверка результата

```cmd
route print
```

Ожидаем увидеть:

```
10.27.0.0    255.255.0.0    10.1.216.100    1
```

---

## Удаление маршрута

Если маршрут добавлен ошибочно:

```cmd
route delete 10.27.0.0
```

---

## Обратный маршрут

Если вы настраиваете сервер **в одну сторону**, убедитесь, что:

* VPN-шлюз или удалённая сторона
* **знает маршрут обратно** к сети сервера

Без этого соединение будет односторонним.

## Быстрый чеклист администратора

* [ ] Подсеть есть в `route print`
* [ ] Маршрут постоянный (`-p`)
* [ ] Шлюз — VPN / L3
* [ ] Маска корректная
* [ ] Метрика ниже default
* [ ] Проверен обратный маршрут

## Вывод

Постоянные маршруты — это **базовый, но критически важный инструмент** в Windows-инфраструктуре.
Во многих инцидентах с RDS, VPN и доменом проблема решается **одной строкой `route -p add`**, если понимать, как работает маршрутизация.

> Если что-то не работает через VPN — **сначала `route print`**,
> потом firewall,
> и только в конце — сервисы и домен.
